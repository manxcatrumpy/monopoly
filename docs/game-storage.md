# 完整存檔與歷史局 — 第二階段重構

## 資料模型

`game-state.js` 是目前局、存檔和歷史快照的共同格式來源。新格式為：

```json
{
  "schemaVersion": 2,
  "currentGame": { "roundNum": 1, "turnNum": 1 },
  "history": [],
  "settings": { "customDecks": { "action": null, "boost": null } }
}
```

上方只示意根結構。完整局資料包含玩家、分數、計時、文明目標、日誌、待抽卡、
領航者歸屬、輪次行動狀態、天氣排程與鎖定／調節結果、救濟盤點旗標，以及
勝利、終局與時間到的通知旗標。每位玩家保留救濟名額、自選低點、庇護起迄輪次和里程旗標。

共用牌組存在 `settings`，切局不會隨歷史還原。開新局與下一局使用
`createGame()` 建立全新局資料；整個遊戲的重置才清除共用設定與歷史。
卡牌選擇、調分草稿、彈窗、儲存提示等暫時 UI 狀態不序列化。

## 保存與相容性

- 新格式寫入 `fuhui-dashboard-state-v2`；僅在新儲存鍵不存在時，讀取舊鍵
  `fuhui-dashboard-state-v1`。舊頁面繼續寫入 v1 時，不影響 v2 資料。
- 轉換前將原始字串保存至 `fuhui-dashboard-state-v2-backup`，並保留 v1 原檔。
  備份失敗時不覆寫遊戲存檔，畫面顯示尚未保存的提示。
- 支援舊平面狀態、`previousRound` 單一快照、舊布林救濟名額與缺少選用欄位的資料。
- 先驗證、遷移全部資料，再替換記憶體中的狀態。損壞 JSON、無效分數、重複玩家 ID、
  損壞歷史或不支援的格式版本都不會局部載入，也不會被背景存檔覆寫。
- 開新局或重置若將取代無法讀取的存檔，必須經使用者確認，且先備份原始內容。
- `serialize()` 只保存模型定義的欄位；不將 UI 草稿或臨時欄位寫入。
- localStorage 寫入失敗會顯示持續提示；下一次成功保存後清除提示。

## 歷史切換

`snapshotGame()` 產生完整獨立副本，並將執行中的計時結算至封存當刻，存成暫停狀態。
目前正在玩的局不因讀取快照而改變。重新整理仍沿用原本起算時間；封存的局不會計入離開期間。

`swapHistory()` 將目前局完整封存到選中歷史的槽位，並將該歷史完整還原為目前局。
兩局可以反覆切回；天氣、待抽卡、救濟與通知旗標不會交叉混用，資料也不共用物件參照。
歷史局還原後保持暫停，按「開始」才接續計時。

切局時會清除當局 UI 草稿、關閉相關彈窗，取消執行中的救濟彈窗。
等待中的救濟及其他局操作會檢查原本局物件是否仍為目前局，避免舊回呼作用到另一局。
新玩家 ID 的起點取自目前局與所有歷史，避免切回或載入後與已記錄玩家重複。

## 無法補回的舊欄位

舊歷史若未記錄天氣、待抽卡或救濟盤點結果，無法推回當時的真實資料。
遷移時保留分數等已記錄資料，未記錄欄位採該局自己的預設值，並在
`incompleteFields` 留下缺漏清單。歷史列表、詳情與切回提示會明確顯示缺漏。

舊歷史在救濟界線後若缺少盤點旗標，視為界線已經過，避免切回時重播救濟盤點。
缺少舊通知旗標時依封存分數與時長補齊，避免再次宣告已完成的勝利或時間到。
天氣鎖定值不會用目前局或封存分數猜測。

原始備份、儲存失敗與重試、損壞／未來格式保護，以及切局時取消舊非同步操作。
