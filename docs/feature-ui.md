# 功能 UI 模組 — 第六階段重構

`app.js` 從 3,028 行縮至約 1,600 行，將主要畫面與事件拆成七個功能模組。
分數、倍率、救濟審核、輪次、歷史交換與存檔仍由原本的流程處理；
模組透過資料讀取介面與操作回呼連接，沒有另建一份遊戲狀態。

## 模組責任

| 檔案 | 負責內容 | 交回 app 的操作 |
|---|---|---|
| `ui-players.js` | 玩家卡、福慧文明、庇護徽章、行動旗標與調分／起始點按鈕事件 | 改名、移除、調分、起始點加分、標記行動 |
| `ui-setup.js` | 開局表單、人數、初始分數輸入、文明目標顯示與十面骰動畫 | 套用開局資料 |
| `ui-cards.js` | 一般／雙人／抉擇卡、收受者選單、卡牌目錄、牌組管理、檔案與貼上介面 | 抽牌、套用獎勵／抉擇、驗證與套用匯入、重設牌組 |
| `ui-history.js` | 歷史清單、唯讀明細、返回及切回按鈕 | 確認與交換歷史局 |
| `ui-weather.js` | 調節表單、花費輸入、剩餘分數與升級預覽 | 低點確認、扣分與調節提交 |
| `ui-feedback.js` | toast、一般確認、救濟提示、日誌與待抽卡清單 | 清除待抽卡；救濟提示回傳選擇，審核與補分仍由流程處理 |
| `ui-exchange.js` | 交易所公告、購買表單、庫存、導航與投資觀察呈現 | 購買入庫、啟用投資、使用導航、開始擲骰 |
| `ui-highlight.js` | 金句輸入、預覽、日期、字數與圖片下載介面 | 經注入的 renderer 產圖與通知 |

`app.js` 保留 `renderAll()` 的協調、頂部摘要更新、調分／起始點操作所需的
即時預覽與草稿，以及少量轉交 UI 的薄入口。這些入口不複製模板或規則。
玩家改名、移除確認和待抽卡清除改為明確的 app 命令；
等待移除確認後也檢查局與玩家身分，防止舊確認刪除替換後的玩家。

## 相依與生命週期

每個檔案提供 `create({...})` 工廠，可由瀏覽器全域載入，也可在 Node 直接載入。
工廠宣告所需的 DOM 查詢、翻譯、格式化、規則讀取及操作回呼。
建立工廠時不查詢 DOM，不安裝事件；由啟動流程在 DOM 準備後呼叫 `bind()`。
固定控制只綁定一次，重新渲染會重建的控制在該次渲染中綁定。

`getGame()` 與 `getState()` 每次讀取目前的狀態，不能在建構時捕捉舊局。
歷史切換、重置與載入替換整個 state 後，原模組仍讀到新資料。
畫面只讀遊戲／歷史／共享設定；改變遊戲資料必須使用傳入的操作回呼。
ESLint 對 `ui-*.js` 關閉 app 自訂全域及隱含的 `document`／`window`，
遺漏注入會報錯，避免逐步長出跨檔全域相依。

開局的 `setupTmp` 與抽卡的 `cardDraft` 是明確傳入的 UI 草稿，允許表單與選項修改；
它們不在 `state`，也不進存檔或歷史快照。切局繼續經 `clearGameUi()` 清理。
所有彈窗仍由第四階段的管理器排序與取消；開局彈窗關閉時會停止骰子的
拋擲與待機動畫，避免隱藏視窗仍保留動畫。
金句下載透過 `getRenderer()` 在操作當下取得 html2canvas，保留未載入時的提示。

七個模組都在頁面先於 `app.js` 載入，列入 Service Worker 離線清單，
並沿用現有靜態建置複製到 `dist/`；沒有新增打包工具或執行期套件。

## 驗證

`npm run test:all` 執行全部驗證。既有流程測試透過 `scripts/ui-sources.js`
載入 HTML 宣告的同一批 UI 檔案，不使用替代 UI 實作。
語系 key 檢查也涵蓋七個模組；離線資產測試檢查頁面上每個本機腳本。

新增的 Node 測試驗證：模組載入不依賴已就緒的 DOM、對凍結的遊戲與歷史進行
渲染不寫資料、不觸發存檔、替換 state 後讀到新資料、重複綁定不重複抽牌，
以及跨局的延遲移除確認不會刪除新玩家。

保留第五階段的十個端到端案例，再補五個功能 UI 案例：實際骰子動畫與開局、
一般雙人卡、條件抉擇卡、金句預覽，以及玩家改名／移除。
第七階段另加入 `ui-pwa.js` 與十個 PWA 案例，並自動驗證離線金句圖片匯出；
目前 Chromium 與 WebKit iPad 模擬各執行二十五個案例，實機 Safari 仍需人工驗收。
