- 狀態：已拍板，可開工
- 日期：2026-09-12
- 適用：福慧大富翁 Dashboard（本 repo，主持人 iPad 控制台）
- 來源：設計規格 v1.0 Final，已拿掉福慧交易所，並依討論定案

本文件只寫本 repo 做得到、且已拍板的行為。福慧交易所、及時雨、平安符、精準導航、天使微投不在範圍內。

名詞對齊程式：

| 規格用語 | 本 repo |
|---|---|
| 輪次 | `state.turnNum`（第 1 輪、第 2 輪…） |
| 局 | `state.roundNum`（開新局／下一局會換一批玩家） |
| 文明現值 | `totalCiv()` |
| 文明目標 | `state.civGoal` |
| 終局倒數 | `sprintActive()`（最後 `ENDGAME_MINUTES` 分鐘） |
| 氣象情報輪 | `getPhase(turnNum).phase === 'REPORT'` |

## 0. 設計意圖

前期運氣不好導致福報或智慧歸零時，不是遊戲結束，而是國家救濟。每人每局一次。不是獎勵：主動策略、氣候調節、主持人改分，系統都不自動救。

## 2. 設定（`config.js`）

在 `GAME_CONFIG` 新增區塊，數值可調、邏輯讀設定。建議：

```js
RELIEF: {
  EARLY_TURNS: 3,       // 第 1–3 輪無條件可救（含第 3 輪）
  RESTORE_TO: 3,        // 恢復目標點數
  SHELTER_TURNS: 2,     // 庇護長度：救濟輪次 N 的 N+1 … N+SHELTER_TURNS
  LATE_CIV_PERCENT: 25  // 第 4 輪起：文明現值/目標 < 此值才可救（等於門檻不救）
}
```

倍率放進既有表，與天氣／終局同一形狀：

```js
MULTIPLIERS.SHELTER: { gain: 1.5, loss: 0.5, labelKey: 'relief.shelter_label' }
```

`applyMult()` 維持 `Math.round(val * rate)`，不必為庇護開第二套捨入。

對照表（實作後用這張驗）：

| 原始 | ×1.5 加分 | 原始 | ×0.5 扣分 |
|---|---|---|---|
| +1 | +2 | -1 | 0 |
| +2 | +3 | -2 | -1 |
| +3 | +5 | -3 | -1 |
| +4 | +6 | -4 | -2 |
| +5 | +8 | -5 | -2 |

文明（`civ` / `civAll`）不吃任何倍率，含庇護。

## 3. 狀態

### 3.1 玩家欄位（`makePlayer`）

```js
reliefUsed: false,        // 本局是否已執行過救濟
shelterFromTurn: null,    // 庇護起始輪（含），未啟動為 null
shelterToTurn: null       // 庇護結束輪（含）
```

舊存檔沒有這些欄位時：`reliefUsed === true` 才當已用；其餘當未用、無庇護。`load()` 對每個 player 補預設。

新局／下一局走 `makePlayer`，自然重置。`snapshotRound()` 已深拷 `players`，歷史切回會帶這些欄位，不必另存。

### 3.2 每人一次的範圍

同一 `player` 物件、同一局（`roundNum`）最多執行一次 `executeRelief`。  
與歸零幾次、哪一項無關。用過之後任何入口都不再自動救，也不再顯示按鈕。

---

## 4. 什麼叫可救（條件層）

函式建議：`reliefPhaseOk()`，與玩家無關。

```
若 turnNum <= RELIEF.EARLY_TURNS
  → 可救
否則若 totalCiv() * 100 < state.civGoal * RELIEF.LATE_CIV_PERCENT
  → 可救
否則
  → 不可救
```

用整數比較，不要算浮點百分比。`25/100` 等於門檻 → 不可救。`civGoal === 0` 時後期視為不可救。

`reliefEligible(player)`：

```
!player.reliefUsed && reliefPhaseOk()
```

按鈕還要加上「目前福報或智慧至少一項是 0」。  
自動救還要加上「本筆至少一項新歸零」（見 §6）。

---

## 5. 什麼叫歸零（自動救專用）

對單一 stat（`fortune` 或 `wisdom`）：

```
本筆開始前 old > 0  且  本筆結束後 new === 0
```

`new` 以 `setStat` 夾完下限為準（扣穿也算）。  
`old === 0` 且 `new === 0`：不是歸零，不自動救。

文明歸零與救濟無關。

---

## 6. 各改分入口

檢查必須在**該入口整筆加減之後**，不可掛在 `setStat` 裡（否則同一筆兩項先後歸零會救到一半）。

### 6.1 抽卡套用 — 跳出提示，不自動執行

入口：`applyCardReward`、`applyChoiceCard`。

對每一位收受者（雙方卡逐人）：

1. 記下該人 `old.fortune`、`old.wisdom`
2. 用**該人**的 `scoreMultiplier(playerId)` 計算福慧加減後 `setStat`
3. 文明照舊、不吃倍率
4. 若 `reliefEligible(p)` 且（福報新歸零或智慧新歸零）→ 跳出 §7 提示，主持人按「啟動救濟」才 `executeRelief`
5. 同一張卡多人符合：依收受者順序逐人提示
6. 已經是 0 再扣同一項：不出提示

卡片「附加」效果仍是主持人手動、走加減分，本路徑不管。

### 6.2 加減分 — 不自動救，改跳出提示

入口：`applyAdjust`。

只改分數。若這一筆讓福報或智慧從正數變成 0，且 `reliefEligible(p)`，立刻跳出提示請主持人按「啟動救濟」或「取消」。不在計分卡放按鈕。

同一輪已提示過且主持人選稍後，不再重複問；之後若另一項新歸零，會再問一次。

### 6.3 氣候調節 — 不救、不出提示

入口：天氣調節 submit（`chargeWeatherAdjust` + `setStat`）。

主動拿福慧換文明，屬玩家選擇，不是運氣不好。歸零**不自動救、不跳出啟動提示**。分數維持 0，額度保留（之後若因抽卡從正數歸零，仍可自動救）。  
這筆扣福慧**不套庇護倍率**（見 §8.3）。

### 6.4 起始點加分

入口：`scoreOrigin`。只加分，不觸發救濟。  
若該人在庇護中，福慧加分要吃庇護 ×1.5（與終局已 ×2 同一範圍）。

### 6.5 開局骰初始值

`applySetup` 可略過「福慧為 0」警告。開局當下不跑救濟。之後抽卡／按鈕才適用。

## 7. 執行救濟 `executeRelief(playerId)`

前置：呼叫端已確認 `reliefEligible`。此函式內再擋一次 `reliefUsed`，避免重入。

當下分數（已套完本筆加減）：

| 當下 | 動作 |
|---|---|
| 福報 === 0 且 智慧 === 0 | 兩項都 `setStat(..., RESTORE_TO)` |
| 只有福報 === 0 | 只恢復福報 |
| 只有智慧 === 0 | 只恢復智慧 |
| 兩項都 > 0 | 不應進來；直接 return |

恢復是**設成** `RESTORE_TO`，不是加 3，不走倍率。

接著立刻：

```
p.reliefUsed = true
p.shelterFromTurn = state.turnNum + 1
p.shelterToTurn = state.turnNum + RELIEF.SHELTER_TURNS
```

當輪（N）不吃庇護。第 N+1、N+2 輪吃（`SHELTER_TURNS === 2`）。

然後：全場彈窗、寫 log、`save()`、更新該玩家卡與 topbar。

本 repo 沒有逐步 Undo。誤按按鈕只能用加減分把分數改回去；`reliefUsed` 與庇護窗口**不會**因此清除。v1 不做「撤銷救濟」。

---

## 8. 倍率 `scoreMultiplier(playerId)`

現行 `scoreMultiplier()` 是全桌一份，且終局已優先於天氣。改成吃 `playerId`（或 player）。無玩家時（卡片尚未選人）維持全桌：終局 > 天氣 > 1。

對指定玩家，由上而下第一個符合就用：

1. `sprintActive()` → `MULTIPLIERS.ENDGAME`（×2 / ×2）  
   庇護欄位不清除。終局在本 App 會持續到時間到；「終局結束後恢復庇護」不必做額外狀態機，時間沒到且仍在窗口內則下一步會自然套到庇護。
2. 該玩家 `reliefUsed` 且 `turnNum` 在 `[shelterFromTurn, shelterToTurn]`（兩端含）→ `MULTIPLIERS.SHELTER`（×1.5 / ×0.5）
3. 本輪為氣象情報輪且有鎖定天氣 → 該天氣倍率
4. 否則 ×1 / ×1

`id` 建議：`ENDGAME` / `SHELTER` / 天氣 id / `null`。預覽與 log 用 `id` 顯示標籤。

### 8.1 必須改成逐人倍率的呼叫點

| 位置 | 作法 |
|---|---|
| `applyAdjust` / `renderAdjustPreview` | 已是單人，改傳該 id |
| `scoreOrigin` / `openOriginModal` | 已是單人，改傳該 id |
| `applyCardReward` | **不可**再算一份 `r` 套給所有人；每人 `scaleReward(..., scoreMultiplier(pid))` |
| `applyChoiceCard` / `choiceEffects` | 套用時逐人算 `each`。預覽在未選人時用全桌倍率 |
| `rewardLineHtml` / `sideLineHtml` | 未選人：全桌（終局／天氣）。選了收受者後可重繪該人倍率；雙方且兩人倍率不同時，套用仍逐人，預覽可用全桌 + 實際以套用為準 |

### 8.2 庇護中的終局

終局覆蓋庇護的**計算**，不覆蓋徽章上的窗口。終局 banner 已存在，不必另做「終局結束後接回庇護」的計時器。

### 8.3 氣候調節扣點

讀輸入、扣福慧時用原始點數，不經 `scoreMultiplier`。庇護中的人換文明仍是 3 福慧換 1 文明。

## 9. UI

### 9.1 全場彈窗（自動救與按鈕共用）

新增 modal（比照 `#confirm-modal`），不可用 toast 代替。主持人按「知道了」關閉。多人連續救濟：關一則再開下一則。

文案（i18n，三種）：

**只恢復福報或只恢復智慧**

```
【社會福利救濟啟動】

{name}的{stat}跌到最低點了。
國家保護機制啟動。

恢復{name}的{stat}到 {restore} 點。
接下來兩輪，{name}會被眷顧——
好事會加倍，壞事會減半。

相信無常也帶著轉運。
```

`stat` 為「福報」或「智慧」。

**兩項都恢復**

```
【社會福利救濟啟動】

{name}的福報與智慧跌到最低點了。
國家保護機制啟動。

恢復{name}的福報與智慧到 {restore} 點。
接下來兩輪，{name}會被眷顧——
好事會加倍，壞事會減半。

相信無常也帶著轉運。
```

log 寫一行可檢索的短句，例如：`{name} 社會福利救濟：恢復{items}到 {restore}。幸運庇護：第 {from}–{to} 輪`。

### 9.2 計分卡：庇護徽章

在 `buildPlayerCard` / `updatePlayerCard`：當 `turnNum` 落在該人庇護窗口內，顯示：

```
幸運庇護中 · 第 {from}–{to} 輪（目前第 {n} 輪）
+增加 ×1.5  -減少 ×0.5
```

窗口已過或未開始（含救濟當輪 N）：不顯示徽章。當輪剛救完只看得到分數已是 3，徽章從下一輪才出現。

### 9.3 主持人確認提示（取代計分卡按鈕）

計分卡不放「啟動救濟」。加減分造成新歸零時，跳出全場 §7 文案，請主持人按「啟動救濟」或「取消」。氣候調節歸零不出此提示。

- 標題：社會福利救濟
- 說明哪一項歸零、恢復點數、庇護兩輪
- 「取消」／「啟動救濟」

按「啟動救濟」→ `executeRelief`（接著出全場敘事彈窗）。按「取消」→ 分數維持 0，額度保留。

### 9.4 加減分預覽

`renderAdjustPreview` 用該玩家 `scoreMultiplier(id)`。庇護中應看到 ×1.5／×0.5 後的預覽。終局中仍是 ×2／×2。

現有「這是本輪行動」勾選不動，與救濟無關。

### 9.5 說明頁

`locales/*/json` 的 `guide` 加一小節：前 3 輪（或文明 < 25%）歸零可救、每人一次、抽卡與加減分跳出提示由主持人啟動、氣候調節不救、庇護下兩輪、終局覆蓋。

## 14. 手動驗收（主持人台）

1. **第 2 輪抽卡福報 2→0**：跳出 §7 提示；按啟動後福報=3、當輪無徽章；第 3、4 輪有徽章；第 5 輪徽章消失。選稍後則維持 0。  
2. **同一張卡福報與智慧都從正數→0**：一則提示；按啟動後兩項都=3，只用一次。  
3. **第 2 輪加減分福報→0**：跳出 §7 提示，不自動恢復。選稍後則維持 0；選啟動則恢復（若智慧也是 0 則兩項都恢復）。  
4. **轉贈福報到 0（稍後），再抽福報 -1**：仍是 0，不出提示（已經是 0）。  
5. **轉贈福報到 0（稍後），再抽智慧 4→0**：跳出提示；按啟動後兩項都=3（情況 A）。  
6. **已用過後再抽到 0**：不救、不出提示。  
7. **氣候調節把福慧換成 0**：不自動救、不出啟動提示，分數維持 0。  
8. **第 4 輪且文明 ≥ 25% 目標**：抽卡歸零不出提示。  
9. **第 4 輪且文明 < 25%**：與第 1 點相同可救。  
10. **庇護中 +1 福報** → +2；**-3 福報** → -1。  
11. **庇護中遇上終局**：加減 ×2／×2；徽章窗口仍在。  
12. **庇護中遇上氣象情報輪（非終局）**：用 ×1.5／×0.5，不用天氣。  
13. **救濟當輪是情報輪**：當輪扣分仍用天氣；恢復 3；庇護從下一輪才開始。  
14. **雙方卡一人庇護、一人沒有**：套用點數不同；各走各的啟動提示。  
15. **舊存檔無新欄位**：當未用過，不噴錯。  
16. **氣候調節、庇護中的人扣 3 福**：實扣 3，不是 2 或 1。
