依據：使用者提供的《福慧大富翁》設定版 V.8 文字擷取，P.45、47–49、52、55、58–60。
本文件記錄實作規劃與已確認決策。V.8 卡牌、角色獎勵、條件選項及本人文明豁免已完成實作；現行欄位與相容性詳見 `rules-decks.md`。

## 1. 範圍與現況

- 更新前共好加速卡 20 張，本次新增 10 張，完成後共 30 張。
- 更新前行動指令牌 34 張，本次新增 8 張，完成後共 42 張。
- 原有卡牌保留；更新明確列出的卡文、獎勵與抉擇效果。
- 繁中、簡中、英文牌組同步，避免切換語言後規則不同。
- 「全場／全體文明 ±N」沿用目前定義：每位場上玩家的個人文明各 ±N，再加總為集體文明。若原稿意指集體總值只變動 N，需另訂分配方式。

規劃時 `deck-model.js` 已支援單卡覆寫分類獎勵、雙人卡、兩個以上的抉擇選項，以及 `each`／`civAll`。本次已補齊以下缺口：

1. 條件卡只接受兩選項，UI 依門檻強制選定其中之一，無法表達低文明時再自由二選一。
2. 一般卡只支援單人或雙方相同獎勵，附加獎勵 `side` 僅顯示文字，沒有自動結算。
3. 全體文明效果目前一律套到所有人，無法直接表達「只有本人免扣」。

## 4. 資料模型與計分設計

### 4.1 條件選項

保留舊 `conditional: { civGte }` 的二分支行為；為新卡增加明確的選項適用條件，例如每個選項可有 `availableWhen: { civGte: 20 }` 或 `{ civLt: 20 }`。

生態紅利用三個平行選項：高文明紅利、低文明 A、低文明 B。高文明只允許紅利，低文明允許 A／B。避免引入巢狀卡牌。

- 驗證器檢查條件格式、非負整數門檻，以及新舊條件格式不可混用。
- UI 顯示目前集體文明與適用選項；只有一個有效選項時可自動選取。
- **真正套用時再次檢查條件**，避免卡片開啟後玩家分數變更，仍能送出失效選項。
- 目錄顯示所有分支及各自門檻。

### 4.2 角色與參與者獎勵

保留 `reward`／`both`／`each` 的舊資料語意，新增結構化附加獎勵，表達「解答者」與「參與者」的角色、可選人數與獎勵。

- 跨界學習：一位發問者、一位不同的解答者，獎勵分別計算。
- 靜心錨定：一位帶領者，多位實際參與者；只對勾選的人發獎。
- 跨越情緒：本次只修改文字範例，維持單一收受者，不新增多人獎勵操作。
- 明確區分「同一獎勵重複勾選」與「同一人合法兼任兩角色」；是否可兼領由卡牌規則決定。
- 新效果必須由資料欄位驅動，不以繁中卡名判斷，也不從 `side` 文字解析數字。
- 已改為自動計分的附加效果，移除「主持人另行手動加分」提示，避免重複發放。

實作欄位為 `extraReward: { role, reward }`，其中 `role` 為 `answerer` 或 `participants`；不支援任意程式腳本。

### 4.3 全體文明排除本人

抉擇選項新增明確的全體效果排除規則，例如 `civAllExclude: 'actor'`。補救分支保留 `civAll: -1`，結算時跳過行動者。

不使用「先全體扣 1，再補本人 1」的兩次結算，避免文明為 0 時誤加分，也避免中途觸發里程、勝利等事件。

### 4.4 共用結算

在 `game-rules.js` 建立純函式，將卡牌、選項、角色選擇及當下玩家狀態轉成完整分數操作清單，供預覽與實際套用共用。

- `app.js` 將完整清單一次送入既有 `settleScoreChanges()`，維持合併後才夾零及既有里程／交易所／救濟流程。
- 福報、智慧按各自收受者的既有天氣、終局及庇護規則計算；文明沿用目前不受倍率影響的規則。
- 抉擇成本延續既有卡牌的救濟處理方式，本次不修改全部舊卡的 `selfSelected` 政策；所有福慧實際受損的卡牌收受者仍走既有救濟檢查。
- 只把主要行動者送入 `markCardActor()`；解答者／參與者獲獎不額外消耗回合。
- 日誌列出行動者、解答者／夥伴／參與者、所選分支與實際效果；非收受者的全體扣分也要可追查。
- 套用中停用按鈕，避免等待確認或救濟視窗時重複結算。

## 6. 建議實作順序

1. **確認規則**：先釐清下一節，固定各張卡的獎勵對象與效果對照表。
2. **擴充資料與純計分**：完成條件、角色獎勵、全體排除與驗證，保留舊牌組相容性。
3. **接上抽卡操作**：角色選擇、參與者勾選、預覽、套用防重複及目錄同步。
4. **更新三語牌組**：修改舊卡、新增 18 張、移除已自動化效果的手動提示。
5. **驗收與文件**：跑測試、lint、build、瀏覽器及離線更新檢查，附上變更清單。

步驟 2、3 應先於新牌組上線，避免畫面可抽到卡、計分卻仍依舊規則執行。

## 9. 更新前補救機制與 V.8 差異

更新前「文明扣分」六張牌都有兩個互斥選項：主持人選擇「行動後果」或「補救機會」，再按套用。系統只結算所選分支，不會先扣行動後果再執行補救，也沒有事後自動退還文明的流程。完成演練或承諾由主持人判定。

下表為基礎效果，福慧實際數值仍依既有倍率規則計算：

| 卡牌 | 選擇行動後果 | 選擇補救機會 |
| --- | --- | --- |
| 廚房無名氏 | 全體文 -1 | 本人福 -2、慧 +1、文 +1 |
| 已讀不回 | 全體文 -1 | 本人福 -1、慧 -2 |
| 正義魔人 | 全體文 -1 | 本人慧 -2 |
| 啊，忘記關了 | 全體文 -1 | 本人福 -2、慧 -1 |
| 垃圾疊疊樂 | 全體文 -1 | 本人福 -1、文 +1 |
| 冰箱大地主 | 本人福 -2、全體文 -1 | 本人慧 -1 |

以上更新前六張卡的補救分支均未設定全體文明扣分，所以選擇補救時其他玩家也不扣文明。V.8「自己免扣文明」的文字則指向只有本人豁免、其他人仍扣分，與現行效果有差異，應明確表達於新分支。

「情緒垃圾車」沿用既有二選一操作：A 結算雙方福 -1、全體文 -1；B 只扣行動者智慧 -1、全體文 +1，不再額外疊加 A 的扣分，夥伴不扣智慧。使用者已確認 B 的智慧成本由行動者支付。
