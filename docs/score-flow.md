# 計分流程 — 第一階段重構

## 操作順序

手動加減分、一般卡牌、抉擇卡、起始點、救濟與氣候調節，都透過
`settleScoreChanges(operations, options)` 結算：

1. `game-rules.js` 合併同一玩家的所有分數變更，計算最終分數。
2. 寫入全場受影響玩家的分數與自選低點標記。
3. 依最終分數判斷單項里程、畢業、領航者與自我突破。
4. 每位受影響玩家更新一次計分卡，集中呈現通知、日誌與待抽卡。
5. `processGameEvents()` 檢查集體勝利、終局、時間到及救濟界線。
6. 被迫扣分的操作再檢查個人救濟，經主持人確認後啟動。

操作可傳入 `{ playerId, delta: { fortune, wisdom, civ } }`，或救濟使用的
`{ playerId, values: { fortune, wisdom } }`。同一操作中，個人文明和全體文明
先合併，再將結果夾到零。例如文明 1、個人 -3、全體 +1，最終文明為 0。

## 模組邊界

- `game-rules.js` 不使用 DOM、localStorage 或系統時間，不改動輸入資料；
  直接由 Node 測試載入，也以 `GameRules` 提供給瀏覽器。
- `processGameEvents()` 由遊戲操作、初始化與計時 tick 呼叫，負責狀態轉移；
  時間到以 `pauseTimerState()` 停表，避免透過畫面函式遞迴觸發規則。
- `updateTopbar()` 與 `renderAll()` 只更新顯示，不領取獎勵、不啟動救濟、
  不停表或寫入遊戲旗標。語言切換也只重新呈現畫面。
- `presentGameEvents()` 處理事件的翻譯、通知、日誌與待抽卡，純規則不依賴文案。
- 救濟彈窗仍由 UI 管理；盤點旗標在等待確認前寫入，避免每秒重複盤點。
  執行救濟時再次檢查資格與目前分數。庇護中再次救濟保留既有起點並延長終點。

完整存檔、舊資料遷移與歷史快照已由[第二階段重構](game-storage.md)統一處理。

## 驗證

`npm test` 包含純規則測試、使用最小 UI adapter 的流程整合測試，以及原有計時
重新載入測試。涵蓋混合加減分、雙方卡牌、集體文明、里程重複觸發、畢業降級、
倍率優先序、救濟名額、自選低點、界線盤點和畫面更新的狀態唯讀性。

新增瀏覽器腳本需一併列入 `index.html` 和 `sw.js` 的離線資產。
`npm run build` 會將根目錄 JavaScript 複製至 `dist/`。

## 交易所整合

詳見 [交易所規格](exchange.md)。計分入口新增 `source`，正常遊戲的實際福慧加分會帶出同輪尚未發放的投資文明，合併同一批結算；投資贈點、救濟與退款不計成長。命運／無常來源在寫分前詢問平安符選擇，再以保護後分數判斷里程與救濟。

開市在 `processGameEvents()` 判定，畫面渲染不變更開市狀態；投資退款在觀察期最後一輪結束時結算。庫存、開市、移動與投資發獎紀錄都由共用存檔模型保存。

交易所購買與使用分開：購買只扣固定費用並加入導航／平安符／投資庫存；`activateInvestment()` 才消耗投資庫存、贈送智慧及建立觀察紀錄，不再扣費。觀察起點採啟用輪次，未啟用庫存不參與成長結算或退款。
