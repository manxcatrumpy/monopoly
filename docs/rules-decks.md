# 規則設定、牌組驗證與呈現 — 第三階段重構

## 共用設定

`config.js` 是里程門檻、文明權重、遊戲時長、天氣與救濟設定的共同來源。
瀏覽器使用 `GAME_CONFIG`，Node 直接 `require('./config.js')`；兩者取得同一份
深度凍結的設定。`app.js`、`game-state.js` 與語系插值都從此取值。

`game-rules.js` 新增純函式 `gameMinutes`、`expectedCiv`、`judgeWeather`、
`weatherUpgradeTarget` 與 `weatherPhase`。預覽和實際天氣判定共用門檻；
災害升級採「嚴格超過 80%」的第一個整數，風調雨順採「至少 120%」的第一個整數。
例如預期文明 10.25，災害升級需要 9 點，避免預覽誤報需要 10 點。

分數批次只接受安全整數，合併後才夾到零；取消舊的 32 位元位元運算轉換，
避免大額有效點數溢位成負數。無效操作會在套用玩家狀態前被拒絕。

## 牌組模型

`deck-model.js` 不使用 DOM、翻譯或儲存，提供：

- `inspect(data)`：驗證並回傳獨立副本，失敗回傳語系 key 與欄位路徑。
- `normalize(data)`：使用相同 schema 驗證與轉換，錯誤時拋出例外。
- `normalizeCustomDecks(data)`：存檔載入使用的共用驗證；相容舊空牌組。
- `buildActionPool` / `buildBoostPool`：集中分類繼承、單卡覆寫、抉擇卡與雙方卡的資料整理。

匯入可只提供 `actionDeck` 或 `boostDeck`，另一副牌保留。新匯入拒絕空牌組、
字串／非有限／非整數點數、陣列冒充物件、未知點數欄位、錯誤布林值、缺少必需文字，
以及無效的抉擇選項和條件卡。點數變動上限為 ±2147483647；負點數仍有效。
錯誤指出具體欄位，例如 `boostDeck[0].reward.fortune`。

一般行動卡可以繼承分類 reward，或自行指定 reward；沒有分類 reward 的牌組，
每張一般卡必須自行指定。抉擇卡不繼承分類 reward。舊 `dual` 布林欄位轉成 `both`。
驗證後的副本在等待主持人確認前建立，外部輸入修改不會改變待匯入內容。

存檔載入也驗證完整牌組效果，無效資料不會局部載入。沿用第二階段的原始備份、
儲存隔離與錯誤提示。既有空自訂牌組保持相容，只有新的匯入禁止空牌組。

## 語系與 CSS 邊界

`i18n.js` 先完成 UI 和牌組載入、驗證，再一次替換語系。失敗保留先前完整資料，
舊請求不能蓋掉較新的語言選擇；fallback 事件回報實際載入的語言。
語言偏好無法讀寫時仍可運作，只允許繁中、簡中與英文語系路徑。

里程、畢業、救濟與時間說明使用共用設定插值；一般呼叫的具名參數仍可覆寫預設。
歷史局、牌組來源、抉擇效果與自選低點警告改用語系 key，修正簡中／英文仍引用舊門檻的說明。
自訂卡牌文字保持使用者匯入內容。

`styles.css` 管理全頁、導覽、玩家卡、天氣公告與設計變數；`components.css` 管理
彈窗、起始點／調分控制、抽卡與抉擇、氣候調節及其響應式樣式。
圖層保持一般彈窗 < 救濟 < 確認 < 通知的順序。
[第四階段](modal-management.md) 將彈窗間的排序統一交給管理器；CSS 使用
`--z-modal` 加上管理器設定的 `--modal-order`，通知仍使用 `--z-toast`。

## 驗證

`npm test` 包含三種內建牌組往返、錯誤匯入不改資料、存檔牌組驗證、
規則設定一致性、天氣邊界、語系失敗／fallback／請求競態與 UI key 覆蓋測試。
前兩階段的計分、救濟、計時、歷史與儲存回歸測試一併保留。
`deck-model.js` 列入頁面與 Service Worker 離線資產，建置複製到 `dist/`。


## V.8 牌組與角色效果

預設牌組已統一為三語相同的 42 張行動指令牌、30 張共好加速卡。新增 18 張，
並更新生態紅利、跨越情緒、跨界學習、靜心錨定及啊，忘記關了。
英文原本使用早期不同牌組，本次一併對齊繁中／簡中內容與效果。
既有自訂牌組和歷史局保留；若已啟用自訂牌組，需在牌組管理器還原預設才會使用新版預設內容。

新增資料欄位如下（均由 `deck-model.js` 驗證，支援存檔與匯出／匯入）：

- 一般卡的 `extraReward: { role: 'answerer' | 'participants', reward: {...} }`：
  解答者必須選一位與行動者不同的玩家；參與者可複選，但排除帶領者且不可重複。
  附加獎勵不與 `both` 或抉擇卡混用。跨界學習行動者保留福 +2、慧 +2、文 +2；
  解答者文 +1。靜心錨定帶領者領基礎獎勵，其他實際參與者各慧 +1。
- 抉擇選項的 `availableWhen: { civGte: N }` 或 `{ civLt: N }`：
  每個條件只接受一個非負整數門檻，不能與舊卡級 `conditional` 混用。
  生態紅利使用三個平行選項：文明至少 20 領雙方福 +2；不足 20 可選雙方福 -1、慧 -1，
  或雙方福 -2、全體文 +1。套用時會再次檢查文明門檻。
- 抉擇選項的 `actor: {...}`：只套用到主要行動者的分數效果。
- 抉擇選項的 `both: false`：覆寫雙人卡，該分支只需選行動者。
  情緒垃圾車的附和分支需要雙方，補救分支只由行動者支付智慧 -1、全體文 +1。
- 抉擇選項的 `civAllExclude: 'actor'`：全體文明效果排除行動者。
  啊，忘記關了、永遠的下次一定、隱形佔地王選補救時，其他人仍文 -1，只有本人免扣。
  直接排除該玩家，不用先扣再補；本人文明為零時不會因此增加。

`GameRules.cardOptionAvailable` 與 `planCardOperations` 是條件判斷與分數操作的共同來源，
供卡牌預覽與實際套用使用。預覽按每個收受者的倍率計算並反映零分下限；文明不受倍率影響。
實際套用仍交給 `settleScoreChanges`，包含既有平安符、投資、里程及救濟流程。
主要行動者只記錄一次行動，解答者與參與者領獎不消耗行動。
卡牌套用期間有介面及流程雙重防重複保護。

補救仍是互斥選項：只結算選中的分支，不會先扣原分支再補回。其他既有六張文明扣分牌
中，只有本次明確更新的「啊，忘記關了」改為本人豁免，其餘補救分支沿用既有資料。
跨越情緒只修改範例，仍由一位選定收受者領取分類獎勵。
原稿所稱新增三種共好文明反思目前只提供兩張，因此本次共好牌數為 30。

驗證包含 `scripts/v8-decks.test.js` 的三語效果一致性、19／20／21 門檻、角色排重、
文明豁免、行動者成本、單次結算，以及 `tests/e2e/v8-cards.spec.cjs` 的實際主持操作。
