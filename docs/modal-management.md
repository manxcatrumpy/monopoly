# 彈窗生命週期 — 第四階段重構

## 管理邊界

`modal-manager.js` 專門處理 UI，不讀寫遊戲分數、規則或存檔。
`app.js` 註冊全部 13 個彈窗，設定初始焦點、優先序及遮罩關閉政策，
所有顯示／關閉都經過管理器。新增視窗也應沿用此入口。
模組列入頁面、Service Worker 離線資產與正式建置。

## 堆疊與鍵盤

- 一般彈窗優先序 0，救濟 1，確認 2；同層依開啟時間排序。
- CSS 以 `--z-modal + --modal-order` 呈現堆疊，順序不依賴 HTML 的排列。
- 只有最上層可操作，其餘視窗與頁面背景設為 `inert`。最上層設
  `aria-modal="true"`，下層設 `aria-hidden="true"`，背景捲動暫停。
- 初次開啟移至指定控制；下層新開不搶焦點，重複開啟不重排。
  Tab／Shift+Tab 圍在最上層；關閉回到下層原控制或來源控制。
  來源已被重新渲染移除時，優先回到仍開啟視窗內的可用控制。
- Escape 只取消最上層。所有視窗支援 Escape，各視窗原有的遮罩關閉政策保留。
- 確認與救濟共用一個鍵盤監聽器。Enter 尊重目前聚焦的按鈕，聚焦「取消」
  就取消；輸入法組字、長按重複鍵及文字區換行不會誤確認。
  救濟仍需先勾選理解確認，未勾選不接受 Enter。

背景原本的 `inert` 與捲動設定會在最後一個視窗關閉後還原。
通知保留原本較高的圖層與即時訊息語意。

## 等待操作與切局

`prompt(id, options)` 回傳 Promise；同一 id 的要求依 FIFO 排隊，
不會互相覆寫文字或綁上多個確認處理器。`prepare()` 在真正輪到時執行，
可重查救濟資格並以 `false` 跳過過期要求。
`onOpen({ listen, close })` 提供只對該次開啟有效的事件與完成操作；
關閉時移除事件，舊完成回呼不能關閉下一筆要求。

每筆視窗與要求屬於開啟當下的 `state.currentGame` 物件。
開新局、重置或切換歷史局前，`clearGameUi()` 呼叫 `cancelScope()`，
一併關閉舊視窗、移除其事件並將現有與排隊的 Promise 完成為 `false`。
佇列再次開啟前也檢查目前局，避免舊要求延後跳出。
原有遊戲流程的局身分檢查繼續保留；UI 草稿、焦點與佇列不進存檔。

## 驗證

`npm test` 執行管理器與實際 app 流程的回歸測試，包括圖層排序、焦點還原、
Tab 邊界、一次按鍵只處理一筆、確認 FIFO、事件移除、初始化失敗與切局取消。
天氣調節測試使用實際提交處理器，確認低點警告在調節表單上層；
取消保留原分數與表單，接受才扣點並關閉。原有救濟／抽卡重疊測試一併保留。
Node 的 DOM adapter 不驗證瀏覽器實際排版、命中位置或原生鍵盤行為。

本機伺服器啟動後開啟 `/scripts/modal-browser.html`，會自動執行 7 項
瀏覽器回歸測試並顯示結果，使用真實 CSS、焦點、`inert` 和
`elementFromPoint()` 檢查確認按鈕是否被遮住。測試頁不列入 PWA 快取。
測試頁的鍵盤事件為程式派發；人工驗收仍需在主頁操作實體鍵盤，
確認 Tab／Shift+Tab、Escape、聚焦取消後按 Enter，以及天氣／救濟／抽卡重疊。
